# E2E 테스트 리포트 — 재제출 워크플로우(FR-12) & 알림(FR-13)

- **실행 일시**: 2026-08-21
- **대상**: 프론트엔드 `https://cjk-007-fe.vercel.app` + 백엔드 `https://cjk-007-be.vercel.app` (Supabase Postgres 운영 DB)
- **범위**: 사용자가 요청한 기능 목록(협력사/CJ프레시웨이의 Workflow·댓글·알림·Dashboard)을 분석해 이번 라운드에 추가하기로 고른 2개 기능만 다룬다. 선정 사유와 제외 사유는 `docs/2-prd.md` FR-12/FR-13 각주에 기록했다.
- **실행 방법**: 백엔드는 `node --test`(node:test) 통합 테스트, 프론트는 `npm run build` + Playwright MCP로 실제 배포본을 조작.

### 🐛 발견 및 수정된 버그: 계정 전환 시 알림 캐시 유출

- **현상**: CJ프레시웨이 계정에서 로그아웃 후 협력사 계정으로 재로그인(SPA 내 라우팅, 새로고침 없음) 시, 알림 드롭다운이 잠깐 **직전 CJ프레시웨이 계정의 알림 목록**을 그대로 보여줌. 원인은 `useNotifications`의 TanStack Query 캐시 키(`['notifications', limit]`)가 사용자를 구분하지 않아, 계정이 바뀌어도 같은 캐시 항목을 재사용했기 때문.
- **영향**: 같은 브라우저를 여러 계정이 번갈아 쓰는 상황(로그아웃 없이 재로그인 반복 등)에서 다른 사용자의 알림 내용이 잠깐 노출될 수 있었음 — 개인정보 노출 성격의 버그.
- **조치**: `useNotifications` 쿼리 키에 `user?.id`를 포함하고 `enabled: !!userId`로 변경(`frontend/src/features/notifications/useNotifications.js`). 계정이 바뀌면 캐시 미스로 처리되어 이전 사용자의 데이터를 보여주지 않는다. 커밋 `d7e81ab`로 배포 후 재검증 — 계정 전환 직후에도 유출 없음, 정상적으로 새 계정의 알림만 표시됨을 확인.
