## 1. 배경 및 목적
- 협력사(식자재 제조·공급사)가 제안하는 프로모션을 CJ프레시웨이 담당자가 검토·승인하고 진행 현황을 함께 소통·관리하는 B2B 협업 서비스.
- 프로모션 제안이 이메일·전화·엑셀로 산재되어 전체 현황 파악이 어렵고, 협의 내용이 기록되지 않아 맥락 추적이 어려운 문제, 그리고 승인 권한이 명확히 구분되지 않는 문제를 해결한다.
- 문제-해결 매핑: 산재 문제는 캘린더+프로모션 엔티티로, 기록 부재 문제는 변경요청 엔티티로, 권한 미구분 문제는 액터별 권한 구분과 Do/Don't 규칙으로 해결한다.

## 2. 액터 (역할)
| 액터 | 설명 | 권한/책임 |
|---|---|---|
| 협력사 담당자 | 프로모션을 제안하는 식자재 제조·공급사 소속 사용자 | 프로모션 등록, 캘린더 조회, 변경요청 등록. 등록 후 프로모션 직접 수정 불가 |
| CJ프레시웨이 담당자 | 제안을 검토·승인하는 CJ프레시웨이 소속 사용자 | 프로모션 승인·수정·반려(사유 필수)·취소, 변경요청 확인 및 반영, 캘린더 조회 |

> 참고: CJ프레시웨이 담당자는 단일 역할로 단순화했다. 검토자/승인자 분리 등 세부 역할 차등은 MVP 범위 밖이다.

## 3. 핵심 엔티티

### 사용자(User)
- 설명: 로그인/회원가입을 통해 인증되는 계정. 소속(협력사/CJ프레시웨이)에 따라 권한이 다름
- 속성:
  | 속성명 | 타입 | 필수 | 설명 |
  |---|---|---|---|
  | id | string | Y | 사용자 식별자 |
  | role | enum(협력사, CJ프레시웨이) | Y | 권한 구분 |
  | 소속사명 | string | Y | 협력사 회사명 또는 CJ프레시웨이 |
  | 이메일 | string | Y | 로그인 계정 |

### 프로모션(Promotion)
- 설명: 협력사가 제안하는 판촉 행사. 등록 후에는 협력사가 직접 수정할 수 없고 CJ프레시웨이만 조정 가능
- 속성:
  | 속성명 | 타입 | 필수 | 설명 |
  |---|---|---|---|
  | id | string | Y | 프로모션 식별자 |
  | 제안자 | User(협력사) | Y | 등록한 협력사 담당자 |
  | 대상 품목 | 대상품목id[] | Y | 프로모션 적용 품목 목록 (대상품목 엔티티 참조) |
  | 기간 | 시작일~종료일 | Y | 프로모션 진행 기간 |
  | 조건 | string | Y | 할인율/가격 조건/지원조건 등을 포함하는 조건 텍스트 (가격 조건 포함) |
  | 상태 | enum(제안됨, 검토중, 승인됨, 반려됨, 진행중, 종료, 취소됨) | Y | 프로모션 진행 상태 |
  | 반려사유 | string | N | 반려 시 필수 입력 |
  | 취소사유 | string | N | 취소 시 필수 입력 (EC-04) |

### 대상품목(Item)
- 설명: 프로모션 적용 대상이 되는 상품 정보
- 속성:
  | 속성명 | 타입 | 필수 | 설명 |
  |---|---|---|---|
  | id | string | Y | 품목 식별자 |
  | 품목명 | string | Y | 상품명 |
  | 규격 | string | N | 용량/단위 등 규격 정보 |

### 변경요청(ChangeRequest)
- 설명: 협력사가 승인 전/후 프로모션 변경을 원할 때 남기는 요청 기록. 승인 이후 핵심 조건 변경은 일반 변경과 구분해 이력을 남긴다 (EC-03)
- 속성:
  | 속성명 | 타입 | 필수 | 설명 |
  |---|---|---|---|
  | id | string | Y | 요청 식별자 |
  | 프로모션id | string | Y | 연결된 프로모션 |
  | 요청자 | User(협력사) | Y | 요청한 협력사 담당자 |
  | 내용 | string | Y | 변경 요청 메시지 |
  | 반영여부 | enum(대기, 반영완료, 반영거부) | Y | CJ프레시웨이의 반영 처리 상태 |
  | 승인후변경여부 | boolean | Y | 승인된 프로모션에 대한 변경인지 구분 (EC-03) |

## 4. 엔티티 관계
- User(협력사) - 프로모션: 1:N (협력사 담당자 1명이 여러 프로모션 제안)
- User(CJ프레시웨이) - 프로모션: 1:N (CJ프레시웨이 담당자 1명이 여러 프로모션 검토·승인 담당)
- 프로모션 - 변경요청: 1:N (프로모션과 협의/변경이력은 항상 함께 관리한다)
- 프로모션 - 대상품목: 1:N
- EC-05의 "동일 공급사" 판단 기준: 프로모션.제안자(User).소속사명 기준으로 동일 여부를 판단한다.

## 5. 비즈니스 규칙 및 제약

### Do
- 프로모션을 중심으로 제안 → 협의 → 승인 → 진행 과정을 관리한다.
- 협력사의 제안 권한과 CJ프레시웨이의 최종 결정 권한을 명확히 구분한다.
- 모든 변경요청과 프로모션 상태 변경은 변경 전/후 값과 타임스탬프를 기록한다.
- 프로모션 반려 시 반려사유, 취소 시 취소사유 입력을 필수로 한다.
- 모든 사용자는 로그인 인증 후에만 서비스를 이용할 수 있다.

### Don't
- 협력사가 등록 후 프로모션을 직접 수정하거나 승인하게 하지 않는다.
- 프로모션과 협의 내용(변경요청)을 분리하여 관리하지 않는다 — 반드시 프로모션 엔티티와 연결되어야 한다.
- MVP 범위를 주문·정산·분석 등으로 과도하게 확장하지 않는다.

## 6. 상태(라이프사이클)
- 기본 흐름: 제안됨 → 검토중 → (승인됨 → 진행중 → 종료) | 반려됨
- 반려됨 상태에서 협력사가 재제안 시: 반려됨 → 제안됨
- 승인됨/진행중 상태에서 취소 발생 시: → 취소됨 (EC-04, 취소사유 필수)
- 승인됨 이후 핵심 조건 변경 요청 발생 시: 검토중으로 되돌리지 않고 승인됨 상태를 유지하되, 변경 이력에 "승인후변경"으로 별도 기록 (EC-03). 중대한 변경에 대한 재승인(Re-approval) 절차 도입 여부는 오픈 이슈로 남긴다.

## 7. 주요 시나리오 / 유스케이스
1. 회원가입 및 로그인 (협력사/CJ프레시웨이 구분)
   - 수용기준: 소속(협력사/CJ프레시웨이)과 자격 증명이 유효하면 로그인에 성공해 역할에 맞는 화면에 진입한다.
2. 협력사 담당자가 프로모션(기간, 대상 품목, 조건) 제안 등록
   - 수용기준: 필수 항목을 모두 입력하면 상태가 '제안됨'으로 등록되고 CJ프레시웨이 담당자에게 노출된다.
3. CJ프레시웨이 담당자가 제안된 프로모션을 검토 후 승인/수정/반려(사유 입력)
   - 수용기준: 반려를 선택하면 반려사유 입력 시에만 처리가 완료되고 상태가 '반려됨'으로 변경된다. 승인을 선택하면 상태가 '승인됨'으로 변경되고, 수정 후 승인하면 변경된 조건/기간/대상 품목이 반영된 채로 '승인됨' 상태가 된다.
4. 협력사 담당자가 프로모션 변경요청 등록 → CJ프레시웨이가 확인 후 반영
   - 수용기준: 변경요청을 등록하면 반영여부가 '대기'로 기록되고, CJ프레시웨이가 처리하면 '반영완료/반영거부'로 갱신된다.
5. 월/주/일 단위로 진행 중·예정 프로모션 캘린더 조회
   - 수용기준: 조회 단위(월/주/일)를 선택하면 해당 기간에 겹치는 진행 중·예정 프로모션 목록이 표시된다.

## 8. 예외 케이스 (Exception Cases)
| ID | 상황 | 처리 방침 |
|---|---|---|
| EC-01 | 협력사가 제출 후 프로모션 직접 수정 시도 | 수정 불가 처리, 변경 요청 기능으로 안내 |
| EC-02 | 이미 종료된 프로모션에 대한 변경 요청 | 원칙적으로 변경 불가. 필요 시 CJ프레시웨이 담당자가 프로모션 상태를 재오픈(종료→검토중 등)한 뒤 처리하며, 재오픈 이력을 남긴다. 재오픈은 CJ프레시웨이 담당자만 수행 가능하며, 상태가 '종료' 또는 '취소됨'인 프로모션에 한해 '검토중'으로 되돌릴 수 있다 |
| EC-03 | 승인 이후 핵심 조건(가격/기간/품목 등, 즉 프로모션의 "조건"(가격 포함)/"기간"/"대상 품목" 필드) 변경 | 일반 변경요청과 구분하여 변경 이력에 기록. MVP 기본 동작은 승인됨 상태를 유지하며 재승인 절차는 적용하지 않는다. 향후 정책 확정 시 이 기본값을 변경할 수 있다 |
| EC-04 | 승인 이후 공급사/CJ프레시웨이 사정으로 인한 프로모션 취소 | CJ프레시웨이 담당자만 최종 취소 처리 가능, 취소사유 기록 필수 |
| EC-05 | 동일 상품 또는 동일 공급사의 프로모션 기간 중복 (동일 공급사는 프로모션.제안자(User).소속사명 기준으로 판단한다) | 동일 대상품목 + 동일 공급사 기준으로 프로모션 기간이 하루 이상 겹치면 등록/승인 시점에 경고 메시지를 표시한다. MVP에서는 경고만 하며 등록 자체를 차단하지 않는다 |
| EC-06 | 로그인 인증 실패 | 오류 안내 메시지를 표시한다. 계정 잠금 등 세부 정책은 MVP 범위 밖 |

## 9. MVP 범위

### 포함
- 프로모션 제안 → 협의 → 검토 → 승인/반려 → 변경 → 일정/진행 현황 관리 (Promotion Collaboration & Governance)

### 제외
- 주문·발주·배송·재고 연동
- 주문/정산, 비용 정산 및 매출/ROI 분석
- 재고 실시간 연동
- 협력사 등급 차등(고객관리)
- AI 추천 및 외부 시스템 연계
- 포인트 적립
- 검색 기능
- 그 외 부가적이고 과한 기능
