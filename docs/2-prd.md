# PRD - CJ프레시웨이 프로모션 협업 앱 (v1.0)

> 기준 문서: `1-domain-definition.md` (v1.4). 본 PRD는 도메인 정의서의 MVP 범위를 벗어나지 않으며, 3일/1인 개발 제약을 전제로 작성한다.

## 1. 개요 및 배경

- **목표**: 협력사(식자재 제조·공급사)와 CJ프레시웨이 간 프로모션 제안·검토·승인·협의 과정을 하나의 서비스로 통합하고, 이력을 남겨 추적 가능하게 만든다.
- **문제 정의**: 프로모션 제안이 이메일·전화·엑셀로 산재되어 전체 현황 파악이 어렵고, 협의 내용이 기록되지 않아 맥락 추적이 어려우며, 승인 권한이 명확히 구분되지 않는다.
- **목표 사용자**:
  - 협력사 프로모션 담당자 (약 1,000명 이상)
  - CJ프레시웨이 상품/영업 담당자 (약 800명)
- **대체재/경쟁 환경**: 별도 경쟁 서비스보다 이메일·전화·엑셀 등 기존 수작업 방식이 실질적 대체재이며, 본 서비스는 B2B 프로모션 협업이라는 좁은 문제에 특화한다.

## 2. 목표 및 성공지표

- 프로모션 제안·검토·승인·변경 과정을 하나의 시스템에서 처리해 이메일/전화/엑셀 의존도를 낮춘다.
- 모든 상태 변경과 협의 내용(변경요청)이 프로모션 단위로 이력화되어 추적 가능하다.
- 협력사와 CJ프레시웨이의 권한(제안 vs 최종 결정)이 시스템상 명확히 구분된다.
- 별도의 정량 KPI(전환율, 매출 등)는 MVP 단계에서 억지로 설정하지 않는다. 단, MVP 오픈 후 "프로모션당 변경요청으로 처리된 협의 건수"를 정성적으로 관찰해 기존 이메일 대비 대체 효과를 확인한다.

## 3. 범위 (Scope)

도메인 정의서 9장의 MVP 범위를 그대로 인용한다.

### 포함
- 프로모션 제안 → 협의 → 검토 → 승인/반려 → 변경 → 일정/진행 현황 관리 (Promotion Collaboration & Governance)

### 제외
- 주문·발주·배송·재고 연동
- 주문/정산, 비용 정산 및 매출/ROI 분석
- 재고 실시간 연동
- 협력사 등급 차등(고객관리)
- AI 추천 및 외부 시스템 연계
- 포인트 적립
- 그 외 부가적이고 과한 기능

> "검색 기능"은 초안에서 제외 항목이었으나, 2026-08-24 사용자 관점 점검에서 목록 조회 시 조건/품목명/제안자 소속사명을 찾을 방법이 없다는 실사용 불편이 확인되어 FR-14로 추가했다(아래 4장). 대신 정교한 검색(초성 검색, 통합검색 랭킹 등)은 여전히 범위 밖이다.

## 5. 비기능 요구사항

- **UI**: 반응형 웹 UI 필수. 데스크톱 우선으로 설계하되 모바일 브라우저에서도 레이아웃이 깨지지 않도록 한다. 별도 모바일 앱은 고려하지 않는다.
- **성능**: 특별한 목표치 없이, 목록/캘린더 조회 시 일반적인 웹 서비스 수준의 응답 속도면 충분하다. 별도의 캐싱/최적화 인프라는 도입하지 않는다.
- **보안**: 로그인 인증 필수(모든 사용자는 인증 후에만 서비스 이용). JWT 기반 인증을 사용하며, access token(단기, 만료 시 재발급 필요)과 refresh token(장기)을 함께 발급한다. access token은 클라이언트 메모리(Zustand)에 보관하고, refresh token은 HttpOnly Secure 쿠키에 저장한다. access token 만료 시 refresh token으로 `/auth/refresh` 엔드포인트를 통해 재발급받는다. refresh token 서버 측 폐기(블랙리스트/회전 이력 관리)는 MVP 범위 밖이며 단순 검증(서명·만료, `type` 클레임으로 access/refresh 상호 재사용 방지)만 수행한다. 비밀번호는 해시 저장(8자 이상). 역할(협력사/CJ프레시웨이) 기반으로 API 접근을 구분한다(TOCTOU 상태전이 가드, IDOR 방지 포함). `/auth/login`·`/auth/signup`은 IP당 15분에 20회로 rate limit한다(2026-08-21). 그 외 세부 보안 정책(계정 잠금 등)은 MVP 범위 밖.
- **접근성(A11y)**: 별도 접근성 감사/인증(WCAG 준수 선언 등)은 범위 밖이지만, 출하검사 과정에서 발견된 기본적인 접근성 결함은 수정한다 — label-input 연결, 모달 포커스 이동/Esc닫기/Tab 트랩/포커스 복원, 폼 에러의 `role="alert"` 안내, 키보드만으로의 핵심 플로우 완주, 상태 배지 WCAG AA(4.5:1) 색상 대비(2026-08-21~24).
- **가용성/인프라**: 별도 이중화, 오토스케일링 등은 고려하지 않는다. 1인 개발·최소 예산 전제로 단일 서버 구성.

## 6. 기술 스택 및 아키텍처 개요

- **프론트엔드**: React 19, 전역 상태관리 Zustand, 서버 상태/통신 TanStack Query
- **백엔드**: Node.js + Express
- **DB 접근**: pg (PostgreSQL 드라이버)
- **데이터베이스**: PostgreSQL 17

### 시스템 구성 (텍스트)
```
[React 19 SPA (반응형 웹)]
    - Zustand: access token(메모리) 등 클라이언트 전역 상태
    - TanStack Query: 프로모션/변경요청 등 서버 데이터 fetch/mutate, access token 만료 시 /auth/refresh 호출 후 재시도
        |
        | HTTP (REST API, refresh token은 HttpOnly Secure 쿠키로 전달)
        v
[Express 서버]
    - JWT 발급/검증(access token + refresh token) 및 역할 기반 접근 제어
    - 프로모션/대상품목/변경요청 CRUD 및 상태 전이 로직
        |
        | pg
        v
[PostgreSQL 17]
    - users, promotions, items, promotion_items, change_requests, notifications(2026-08-21 추가, FR-13)
```

- **범위 확장 리스크**: 주문/정산/AI추천 등 요구가 추가로 들어올 수 있으나, 도메인 정의서의 MVP 제외 항목을 그대로 유지해 범위를 지킨다(검색은 FR-14로 예외적으로 편입, 위 3장 참고).
